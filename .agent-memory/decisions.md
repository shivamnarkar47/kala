## 2026-08-23 — generate tool round-trip 400 fixed (toolName was mandatory)
First live multi-turn agent run on the Go-plan transport 400'd at turn 2 ("Invalid request error… messages[2].role"). Root cause found by reading the official CLI's dist bundle (`command-code/dist/cli.mjs` → `toWireMessages`): the wire contract is assistant content = parts of text|reasoning|**tool-call**{toolCallId,toolName,input} and each executed call returns as its own role:"tool" message whose **tool-result part REQUIRES toolName** (CLI defaults it to "unknown"); thinking replays as {"type":"reasoning"} parts. Our converter omitted toolName → no schema branch matched. Also mapped `finish-step` events (rawFinishReason) onto the final done. Diagnostics kept: `KAAL_DEBUG_CC=<path>` dumps a rejected payload; `KAAL_LIVE_CC=1 go test ./internal/gateway -run TestLiveCCGenerateRoundTrip` bills real credits to reproduce. LESSON: the HTTP-400 zod union error lists ALL branches' failures — a failing branch can hide behind another's message; bisect against the reference implementation, not the error text.
